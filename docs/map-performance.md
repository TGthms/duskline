# Weather map data and rendering

Temperature and precipitation use the global DWD ICON spatial grid via Open-Meteo (0.125° grid spacing). Temperature is the model's two-meter air temperature. Precipitation is the forecast water-equivalent amount for the hour ending at the displayed time, with rates below 0.1 mm/h transparent. The city forecast still shows chance of precipitation. The selected frame includes a model run and the exact valid UTC hour. Tiles draw under the existing OpenFreeMap labels; the app overzooms past the maximum weather tile resolution.

Wind uses the ICON ten-meter eastward and northward wind components. The publisher projects both components before calculating speed and bearing. Static arrows on the same forecast frame point in the direction the wind is moving and are omitted below 1.5 m/s. In the wide phone browser check, the wind raster transferred 271 kB and the arrows added 3.6 kB.

At the closest source zoom, precipitation uses four samples per output pixel to antialias partial wet coverage. Opacity represents the area covered, and intensity is averaged only over wet samples. Lower zoom archives use the original sampling budget. New tiles take effect with the next published model run.

The tile publisher runs on GitHub Actions. It reads the spatial temperature, precipitation, and wind components using byte ranges, reprojects them to Web Mercator, and packs one tile pyramid per layer and hour. It publishes 24 hours together and retains previous runs for 48 hours. A Weather Map release is published only after every tile archive has uploaded. A maintainer can trigger **Publish weather map tiles** on `main` to recover after an outage. Cloudflare Pages returns tiles from the appropriate immutable archive and caches each response at the edge for a day. The four-minute manifest can choose a previous complete run that still covers the current hour. This path uses the GitHub repository and Pages project directly.

The publisher selects the most recent complete run across the Open-Meteo regular and native ICON spatial feeds. When the native feed supplies that run, it maps the official native cell centers onto the existing 0.125° grid using nearest distance on a sphere. One lookup table is shared across all hours. The input coordinate-system and array-shape checks protect against feed format changes. Use `--source dwd_icon_global_native` to verify the native path explicitly.

Run `python -m pip install -r tools/weather-tiles/requirements.txt` in a virtual environment, then `python -B -m unittest discover -s tools/weather-tiles` to check the generator. Generate a local complete run with `python tools/weather-tiles/generate.py --output /tmp/duskline-tiles`. Source data: [Open-Meteo AWS Open Data](https://github.com/open-meteo/open-data), [DWD ICON variables and intervals](https://open-meteo.com/en/docs/dwd-api).

The 512-pixel archive reaches the same 4096-pixel world raster as the initial 256-pixel archive. In a wide Pacific view, it reduced each measured frame from 45 to 15 desktop requests and from nine to four phone requests. The phone received 224 kB of temperature tiles and 144 kB of precipitation tiles in that case. Viewport, zoom and the forecast field affect these totals. On the deployed gateway, one 25 kB tile took 548 ms on its first request and 123–155 ms from the edge cache on two repeats. Desktop and phone figures are browser measurements; they do not include physical device battery or weak-network testing.

The vendored PMTiles reader is used by the Pages Function. Pages builds the functions without installing packages. To regenerate the small bundle locally, run `npm ci`, install `pmtiles@4.5.0` and `fflate@0.8.3` with `--no-save --package-lock=false`, and pipe `export { PMTiles, ResolvedValueCache } from "pmtiles";` into the repository's esbuild with `--sourcefile=map-tile-reader.js --bundle --platform=browser --format=esm --minify --legal-comments=none`. Place the output and upstream license notices under `functions/_lib/vendor/pmtiles/`.

## Point forecast layers and fallback

AQI and the forecast layer fallbacks use an aligned latitude/longitude sampling lattice capped at 64 forecast locations per viewport. Neighboring views reuse individual samples in a bounded 256-location cache for eight minutes. The UI labels this data as interpolated estimates. The precipitation fallback displays chance of precipitation with a percentage legend.

Four-corner bilinear interpolation replaces the old all-point inverse-distance field. Spatial buffers now hold four indices and weights per pixel, independent of sample count (about 113 KiB on a 390px phone and 380 KiB at the desktop raster cap). A missing corner produces a transparent local gap instead of extrapolating from distant places. Timestamp matching prevents cached samples crossing midnight from being read at the wrong index.

Air Quality uses US AQI bands and the CAMS global domain through Open-Meteo's air-quality API. The global model's approximate 45 km resolution is disclosed. Sampling never becomes finer than 0.5 degrees. The spatial CAMS files contain pollutant concentrations, so a gridded US AQI replacement must combine the pollutant indices with their respective averaging periods and be checked against published AQI.

`npm run benchmark:map` compares CPU kernels with the historical all-point renderer. Pixel identity is no longer an acceptance criterion because the interpolation model intentionally changed. Unit tests instead verify exact reconstruction of a linear field, local missing-data behavior, stable nearby samples, AQI band boundaries and request budgets. Canvas upload, WebGL and real-device battery costs remain outside this synthetic benchmark.

Startup installs forecast layers at style readiness and keeps the atlas visible until a frame paints geographic features. It does not wait for every tile or optional label/source. Isolated tile failures preserve the usable map. Retryable failures get at most two recovery attempts while the map remains open. A ready renderer, camera, layer and forecast-hour selection survive close/reopen for up to two foreground minutes; backgrounding releases the closed renderer. City detail fades over the returning map instead of revealing the dashboard. Cold-load and WebGL context failures still fall back cleanly, with visibility guards, throttling, cancellation and stable controls preserved.
