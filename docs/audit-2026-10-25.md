# Duskline audit — October 25, 2026

Implementation follow-up: [native experience changes and validation](native-experience.md). The findings below record the original review.

Duskline has a strong foundation: a static app with explicit module boundaries, worldwide forecasts, My Sky and Horizon, lazy weather maps, official public alerts, 30 languages, local forecast snapshots, a versioned offline shell, and optional Cloudflare/D1 background notifications. The most valuable next step is consistency in everyday navigation, accessibility, and forecast visibility.

Reviewed the project documentation, startup and preferences, forecast/provider ownership, saved places, navigation and sheets, map lifecycle, localization, service worker and installation, notification service, responsive styles, and existing test coverage. Visually inspected the running app and phone/desktop reference images. This is a local audit; production configuration and physical-device behavior were not certified.

## Clear bugs fixed

| Trigger | Previous behavior | Fix |
| --- | --- | --- |
| Open a city, then refresh while its initial detail enrichment is slow | The older enrichment could replace the newer forecast | Enrichment now participates in the same per-city request-generation checks as full refreshes |
| Refresh a primary city during a provider outage | The returned fallback was marked saved, but the shared cache could still present it as current | Retained forecasts are marked saved in the cache, preserving the original check time |
| Switch languages on a control with both a tooltip and an accessible label | Only one translation target changed; title-only controls also restored the wrong English value | Each declared attribute/content target now retains and translates its own original value |
| Open an animated sheet, or drag a phone-sized sheet closed | Opening focus could remain behind the sheet during its visibility transition; dragging it closed did not restore focus | Opening retries focus on the following frame if it failed and the user has not moved focus; dragging uses the normal close/restoration path |

Added regression tests that reproduced each bug before its fix. Bumped the offline shell to **v86** so installed apps can receive the changed code through the existing Update flow. No redesign, deployment, or dependency changes.

## Recommended follow-up, in priority order

1. **Make primary-city alerts visible in My Sky.** `product.js` renders weather, planning, hours and days, but no alert summary. The primary city is excluded from the saved-place list, whose rows do render alert badges. Add a compact, severity-aware entry to current alerts on the primary card. This needs a product decision about prominence, unavailable checks and expiry; keep alerts network-only.

2. **Unify modal accessibility.** The map explicitly makes the page header, main content and footer inert. Detail and sheet handling mainly isolates the detail surface and traps Tab. Background content remained exposed in the inspected Settings accessibility tree. Verify VoiceOver navigation on iOS, then use a shared modal-isolation policy that also preserves nested sheet/map returns. This is broader than the sheet focus fixes above.

3. **Bring the primary forecast closer to the top on phones.** In the 430×932 reference, it starts around y=343 after branding, language, greeting, search, navigation and timestamp/place controls. Consider a compact phone header, language in Settings, and persistent thumb-reachable My Sky/Horizon/Map navigation. Keep the desktop layout tailored to its larger space. Prototype before changing the hierarchy.

4. **Make map gestures discoverable.** Viewing or saving an arbitrary point depends on right-click/long-press or keyboard commands. Add a brief contextual hint or first-use instruction. Preserve the deliberate removal of persistent map search and inspection controls documented in the project.

5. **Give the update notice a quieter home.** The current persistent floating Update notice has no Later action and can overlap the content being read. Consider a dismissible notice with a persistent update entry in Settings. Retain explicit activation and the existing retry/recovery behavior.

Maintenance follow-up: `weather/app.js` is about 5,700 lines and `weather-app.css` about 4,700, with many later CSS overrides. Continue extracting cohesive controllers and consolidating rules when those areas change; a broad rewrite would add risk without improving the immediate experience.

## Is this much testing necessary?

**Keep the regression coverage; reduce how much runs for each small edit.** AI maintenance makes independent behavioral checks valuable, but it does not justify testing every detail in every browser. The existing 124 units passed, yet this audit found uncovered bugs: scenario quality matters more than count.

The 127 unit/content tests now finish in roughly one second locally. They are inexpensive and cover useful weather math, missing data, timezones, request races, alert matching, local persistence, localization and push security. The expensive part is repeating the browser suite across four projects, plus a separate visual job. The original 205-case Chromium run took 4.3 minutes locally; the suite now has 207 cases per project, including conditional skips.

Recommended cadence:

| When | Checks |
| --- | --- |
| Each agent edit | Syntax, units and the affected browser scenarios; use mobile WebKit for touch/sheet/PWA changes |
| Pull request | A curated 15–25 core journeys in Chromium and mobile WebKit, plus affected regressions |
| Release / broad shared-runtime change | Complete browser matrix, reviewed visuals and offline upgrades; real Worker integration when notification/backend code changes |

Specific consolidation candidates:

- Merge `smoke.spec.js`'s **units sheet opens** and `regressions.spec.js`'s **Units sheet locks background scrolling and restores the previous page position** into one behavioral scenario with both nonzero scroll restoration and scrolling enabled after close. Their different assertions should be preserved where useful.
- Run the complete 30-language, ten-sheet browser sweep in one engine for localization changes/releases. Use representative Latin, long-label, CJK and RTL locales in the everyday cross-browser checks. Retain cheap all-language key/placeholder checks.
- Keep static metadata/favicon checks primarily in units; the SEO browser test overlaps that coverage. Preserve any distinct HTTP/MIME checks in a small serving smoke check rather than repeating static assertions in every engine.
- Relax or remove exact README slogans, branding markup and arbitrary copy-length assertions when they do not protect a documented requirement. They can reject valid edits while failing to establish that the copy is correct. Keep link integrity, placeholder parity and known translation regressions.
- Run the 24 visual snapshots for UI changes and releases; do not regenerate baselines to silence failures. Provider-only fixes generally need behavioral data tests instead.

Keep request-race tests, missing-versus-zero handling, offline update/recovery, Back/focus/scroll restoration, notification ownership/disable cleanup, and both independently verified push cryptography and the real Worker send check. Those checks cover different failure modes. The documented Worker transport defect is a concrete example of why a passing Node mock cannot replace runtime integration.

No tests were deleted and CI/deployment gates were not weakened in this audit. Implementing the proposed tiers should be a focused follow-up, with the core-journey list reviewed first.

## Validation and remaining acceptance

- JavaScript syntax: 102 files passed.
- Unit/content tests: 127 passed, including three new regression cases.
- Complete Chromium, desktop WebKit and mobile WebKit sweep: 575 passed, 46 intentional skips (7.8 minutes). Includes the 24 visual snapshot comparisons and real offline worker upgrades.
- Final sheet-opening focus adjustment: 18 focused Chrome/desktop WebKit/mobile WebKit checks passed, covering entry/drag return, nested notification settings, sharing, rapid dismissal and preserved sheet scroll.
- Firefox could not launch: its local macOS sandbox/framebuffer setup failed and timed out before any browser assertion. Firefox remains unverified here.
- Locale regeneration produced no generated-file drift; Git whitespace checks passed.
- No screenshot baselines or tolerances were changed.

Physical iOS Home Screen acceptance remains necessary: cold launch and first tap; keyboard open/close; drag and edge-back behavior; VoiceOver modal boundaries; background/resume and rotation; offline relaunch; accepting an update; and actual push receipt. Browser emulation does not establish those device results. Production notification/hosting settings were left unchanged.
